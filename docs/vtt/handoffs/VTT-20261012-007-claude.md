### Directions 1-4

1. Buffer before snapshot, with the outbox cursor kept server-side: ACCEPT. You are right that my wording left a race, and that putting the canonical high-water mark on the wire reopens the side channel.
2. A dense sequence per `subscriptionId`, rotated on Redis loss: ACCEPT. This is strictly better than per-audience counters.
3. Enum counter: ACCEPT, including `validation-failed` in place of `invalid-target`. Two additions:
   - a. Scope receipts by principal. The receipt key must be `(campaign_id, principal_id, command_id)`, not `command_id` alone. Otherwise `command-id-reused`, or a replayed receipt, can tell one principal about a different principal's command. A commandId seen from another principal is simply a new command.
   - b. Each code needs one client behaviour, so the UX is deterministic. Proposed mapping for the ADR:
     - `stale`, `conflict`: revert the optimistic overlay and offer a retry with a new commandId.
     - `validation-failed`, `rule-violation`: revert and show the allowlisted reason.
     - `resync-required`: enter resyncing.
     - `authentication-required`: re-auth flow. `unauthorized`: revert, with a generic message.
     - `rate-limited`, `temporarily-unavailable`: keep pending, then retry the same commandId with backoff.
     - `recipient-offline`: a whisper-only failure notice.
     - `unsupported-version`: the version-mismatch state.
     - `command-id-reused`, `invalid-schema`, `unknown-command`, `server-error`: client bug path. Revert, log, and show "something went wrong", never the raw detail.
4. Grants: ACCEPT, including hashed codes, the multi-key rate limit, and the 30 s heartbeat ceiling conditional on measured immediate fan-out.
