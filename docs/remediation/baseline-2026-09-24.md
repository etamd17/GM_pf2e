## Repository and test baseline

### Test surface

The repository contains 183 tracked test modules. GitHub Actions uses Python 3.11,
installs `requirements.txt` and pytest, parses the Jinja templates, and runs
`pytest -q`; see `.github/workflows/ci.yml`.

The complete Python suite was run in a disposable environment at the audited
commit: 2,356 tests passed, 25 were skipped, and 11 warnings were reported in
1,224.69 seconds. The warnings included pytest class-fixture warnings and Pillow
`getdata` deprecations. This is the regression baseline, not proof of PF2e rules
correctness, because some tests encode legacy rules behavior.

The repository had no tracked browser runner or automated accessibility scanner.
Some Python tests inspect template strings and UI contracts, but those are not a
substitute for rendered keyboard, focus, responsive, or accessibility testing.

## Rendered accessibility and mobile spot check

The local app was rendered in headless Chromium with Playwright at desktop and
mobile profiles. The audit script examined:

- visible interactive elements whose bounding box was below 44 CSS pixels in
  either dimension;
- visible `input`, `select`, and `textarea` elements without an associated
  `label`, `aria-label`, or `aria-labelledby`;
- the presence of common page landmarks; and
- horizontal document overflow.

The exact original viewport dimensions were not retained in the audit notes and
must not be inferred. The table therefore records the preserved counts without
claiming pixel-for-pixel reproducibility of that first run. Future runs are
standardized below.

| Surface/sample | Below 44px target | Unlabelled visible controls | Other retained observation |
|---|---:|---:|---|
| Character builder | 13 / 16 | 2 | No `main` or `nav` landmark detected |
| Character sheet, mobile profile | 45 / 62 | 1 | — |
| Level-up, mobile profile | 7 / 8 | Not retained | — |
| Encounter builder, mobile profile | 49 / 58 | 14 | — |
| Tracker, mobile profile | 33 / 36 | 1 | — |

The 44-pixel check is a product usability target and a coarse risk detector. A
control below 44 pixels is not automatically a WCAG 2.2 AA failure: the AA target-
size criterion uses a smaller minimum and includes exceptions. Conversely, passing
this script would not establish conformance. This was not an axe scan, complete
accessible-name computation, focus-order test, keyboard test, contrast audit, or
screen-reader assessment.

### Source-inspected mobile and accessibility risks

These findings are fixed to the audited commit:

- `templates/mobile_combat.html:5` sets `user-scalable=no`, preventing normal
  pinch zoom.
- `templates/tracker.html:399-428` defines the tracker header and every combatant
  as the same wide seven-column grid. The nearby responsive rule changes a panel,
  not this primary row model.
- `templates/encounter_builder.html:43-58` starts with a fixed side-by-side layout
  and a one-third-width search column, without a page-level small-screen layout.
- `templates/encounter_builder.html:47-58` and `81-114` use placeholder/title text
  for many inputs rather than programmatic labels. Labels at `30-38` also do not
  use `for` to associate them with their controls.
- `templates/_choice_picker.html:23-46` visually implements a modal without dialog
  semantics, an accessible name relationship, or an evident focus contract.
- `templates/player_builder.html:214-295` includes click-driven `div` choice cards
  rather than native buttons.
- `templates/player_sheet.html:3028-3036` and `4807-4822` implement visual tabs by
  toggling classes, without tab roles, selected state, or keyboard navigation.
- `templates/_pc_sheet/_left_rail.html:73-80` includes 22-pixel condition action
  controls, consistent with the mobile target-size count.

## Anonymous live sample

On 2026-09-24, one anonymous request to
`https://tableview.up.railway.app/login?next=/me` returned HTTP 200 with a
5,167-byte body and approximately 151 ms time to first byte.

One request for `/static/css/system.css` observed:

- 208,366 bytes in the uncompressed representation;
- 45,635 transferred bytes with gzip negotiation;
- `Cache-Control: no-cache`; and
- an ETag.

`no-cache` permits storage but requires revalidation; it is not the same as
`no-store`. The local checkout's CRLF working-tree copy was 213,732 bytes, so local
filesystem size and live HTTP representation must not be compared without line-
ending and content-encoding normalization.

The live observations are useful reachability and header samples only. One TTFB
cannot characterize Railway cold starts, regional latency, database latency, or
percentiles, and the protected builder, sheet, tracker, and GM workflows were not
sampled in production.

## Reproduction standard for future baselines

Use a clean checkout and record the commit, operating system, Python/Node/browser
versions, fixture revision, viewport, cache state, and number of samples beside
every result. Never use production credentials or copy production campaign data
into the harness.

### 1. Pin the source and count tracked surfaces

PowerShell:

```powershell
git switch --detach 7aed67303c314e1e9d0218f38e7adcae2326410c
git rev-parse HEAD
(git ls-files 'tests/test_*.py' | Measure-Object).Count
(git ls-files 'templates/*.html' 'templates/**/*.html' | Measure-Object).Count
```

For physical line and working-tree byte counts:

```powershell
$path = 'templates/player_sheet.html'
$item = Get-Item $path
[pscustomobject]@{
  Path = $path
  Bytes = $item.Length
  PhysicalLines = (Get-Content $path).Count
}
```

### 2. Establish the test baseline in a provisioned environment

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe tools/check_templates.py
.\.venv\Scripts\python.exe -m pytest --collect-only -q
.\.venv\Scripts\python.exe -m pytest -q
```

Record collected, passed, failed, skipped, xfailed, and duration separately. Do
not compare a collection run with missing dependencies to CI results.

### 3. Measure server response bodies

Create a new disposable data directory containing only the documented synthetic
fixture, point `DATA_DIR` to it before importing `app`, and use Flask's test client.
For each route:

1. establish the same local campaign/session fixture;
2. make one warm-up request;
3. make five measured requests;
4. assert the expected status and content type;
5. report `len(response.data)` plus median and p95 elapsed server time; and
6. delete the disposable directory after retaining only aggregate measurements.

The core measurement is:

```python
from time import perf_counter

started = perf_counter()
response = client.get(path)
elapsed_ms = (perf_counter() - started) * 1000
print(path, response.status_code, len(response.data), elapsed_ms)
```

Use the exact route set in the response-size table. Do not put cookies, password
values, session contents, character payloads, or environment dumps in output.

### 4. Measure rendered mobile and accessibility indicators

Run every critical journey at these fixed viewport sizes:

- 375x812
- 768x1024
- 1024x768
- 1440x900

For each route and state, wait for the page's explicit ready signal rather than an
arbitrary delay, then record:

- visible interactive-element count;
- count below 44 CSS pixels in either bounding-box dimension;
- visible form controls without an accessible-name source;
- `main`, navigation, heading, dialog, and tab semantics;
- `document.documentElement.scrollWidth > clientWidth` and the element causing
  overflow;
- keyboard traversal, activation, Escape behavior, and focus restoration;
- axe critical/serious findings; and
- a screenshot at each viewport.

Use an isolated local account/campaign storage state. Persist that synthetic
fixture or a setup script with the measurement artifact so the same controls are
visible on the next run. Report 44-pixel findings as usability-target misses, not
automatically as WCAG violations. Run manual NVDA/Chrome and mobile screen-reader
smoke tests for custom dialogs, tabs, sheets, and authoring workflows.

### 5. Sample anonymous live endpoints

PowerShell examples:

```powershell
curl.exe -sS -o NUL -w "status=%{http_code} bytes=%{size_download} ttfb=%{time_starttransfer}`n" "https://tableview.up.railway.app/login?next=/me"
curl.exe -sS -o NUL -w "status=%{http_code} bytes=%{size_download} ttfb=%{time_starttransfer}`n" "https://tableview.up.railway.app/static/css/system.css"
curl.exe -sS --compressed -D - -o NUL -w "wire_bytes=%{size_download}`n" "https://tableview.up.railway.app/static/css/system.css"
```

Run enough samples to report median and p95 if live performance will be used as a
release gate. Anonymous health and static-asset requests must remain separate from
authenticated journey measurements.

## Interpretation and update policy

This baseline should remain immutable. A later audit should add a newly dated
document and compare like-for-like measurements rather than editing these numbers.
If the fixture, route behavior, viewport, compression, or measurement harness
changes, report that difference before drawing a trend conclusion.

The first modernization pull request should turn the manual browser methodology
into a tracked Playwright/axe harness. Until then, repository counts and local
response bytes are reproducible; the original DOM counts are directional because
their precise viewport dimensions were not retained.
