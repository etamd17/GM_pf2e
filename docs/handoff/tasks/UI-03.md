## Fixes

### 1. PF2e GM screen: the polish script never runs (`templates/gmscreen.html` ~1127)
`document.querySelector('.masonry')` returns null (the containers are 4x `.gm-group-grid`), so
the early return disables three features: pin/reorder cards (star button, localStorage
`gmscreen_pinned_v1`), `#comp-search` highlighting, and clickable condition names
(`.gm-cond dt` -> `showCompDetail`).
- Collect cards with `.gm-group-grid .gm-ref-card` (check the real card class). In
  `applyPins`, re-append each card to **its own** parent grid, not one shared grid, or pinning
  moves every card into the first group.
- Test: render `/gmscreen` and assert that the selector the script uses matches elements in the
  page. Also check that pinning keeps a card in its own group (a source-level check is fine).

### 2. Map: the first-scene error throws instead of showing a toast (`static/js/map.js`)
With no scene, the script calls `wireCreateForm()` and returns (~line 9-25) before
`let toastTimer = null;` (~line 74). The create form's catch (~line 2727) calls `toast()`, which
throws "Cannot access 'toastTimer' before initialization".
- Move the toast state (and anything else `wireCreateForm` reaches) above the early return.
- Test: `tests/test_map_scene_lifecycle.py` already slices the early-return guard (~line 189).
  Assert that the `toastTimer` declaration comes before it.

### 3. PF2e builder review step (`templates/player_builder.html`)
- `state.ancFeat` is the feat **object** (~799). Review pushes `{name: state.ancFeat}` (~1627),
  so `(e.name||'').toLowerCase()` (~1634) throws and the Review step renders blank. The chip at
  ~1682 would show "[object Object]". Use `state.ancFeat.name` in both places.
- Stale fields: review reads `state.className` (~1696; the real field is `state.cls`),
  `state.selectedSpells` (~1733; the real field is `state.spells`) and `state.trainedSkills`
  (~1721; never set, so the list leaves out class and background skills). Read the real fields,
  and build the skills list the same way the final save does (~1776).
- Test: in `tests/character_workflows/test_builder_draft_contracts.py` (or a new
  `tests/test_builder_review_step.py`), assert that the review code no longer reads the stale
  names. If practical, add a browser test: pick an ancestry feat, open Review, and check that
  Class, the feat name and the spells render.

### 4. PF2e level-up: the gains rail blocks picker clicks (`templates/player_levelup.html` ~186-198)
`#gains-rail` is `z-index:55`, above the picker modal (`#uni-modal`, z-50). Only
`#gains-rail-body` gets `pointer-events:none` while `body.picker-open`. The rail's own box and
header still catch clicks over the picker's left edge on wide screens.
- Add `body.picker-open #gains-rail{pointer-events:none}` and keep the GM override control
  clickable (`body.picker-open #gains-rail-header{pointer-events:auto}`, or narrower, just the
  switch). Make sure nothing else in the header can then open a second picker.
- Test: a source check on those rules, plus a browser test if you can (open a feat picker at
  1440px and click an option under the rail's column).

### 5. Cosmere loot: deletes, write order, client errors (`app.py` loot routes, `templates/cosmere_loot.html`)
- **(c)** `api_cosmere_loot_delete` (~12060) only removes the ledger entry. The spheres already
  credited to the PC's wallet stay. Debit the stored entry from the same wallet, never below
  zero. If the wallet no longer has enough, refuse with a clear message rather than removing the
  ledger line silently. Entries for "party" (ledger-only, no wallet) just get removed.
- **(d)** The ledger is written (~12038) before the wallet save (~12045-12049), with no rollback.
  Make the order safe: write the wallet first, then the ledger, and undo the wallet if the ledger
  write fails (or the reverse). Either way, one failure must not leave the two disagreeing.
- **(e)** The client clears the form after `r.json()` without checking `r.ok`/`success`
  (~171-174), and `del()` (~156) ignores the response. Check both, keep the form on failure, and
  show the server's message.
- Tests: `tests/test_cosmere_loot.py` and `tests/test_cosmere_loot_to_sheet.py`. Cover: add then
  delete returns the wallet to its old value; delete when the wallet was already spent is
  refused; an injected wallet-save failure leaves no ledger entry.

### 6. Cosmere roster and GM vitals (`templates/cosmere_pcs.html`, `templates/cosmere_gm_vitals.html`)
- The roster shows **maximum** Investiture (`app.py` ~13151 `b.investiture_max()`). Show the
  current value from play state, as "current / max".
- The vitals cards are keyed by name (`data-name`, `_card(name)` ~104). Every
  `cosmere_player_state` broadcast already carries `pid`. Add `data-pid` and look cards up by pid,
  falling back to name only when pid is missing.
- The vitals bars use maximums frozen at render (`data-hpmax` / `data-focmax` / `data-invmax`).
  Add the maxima to the `cosmere_player_state` payload (check every broadcast site: ~825, 8622,
  14588, 14859, 15592) and update the data attributes when they arrive.
- The roster has no live updates. Subscribe through `window.appSSE('cosmere_player_state', ...)`
  (never a raw `EventSource`) and repaint HP / focus / investiture in place. Keep it small: no
  layout change.
- Tests: `tests/test_cosmere_gm_vitals.py` (near `test_board_listens_for_live_state`) and
  `tests/test_cosmere_status.py`. Assert the payload has the maxima and pid, the vitals page
  carries `data-pid`, and the roster subscribes via `appSSE`.

### 7. Campaign delete wording (`templates/campaign_invites.html` ~123-125, `app.py` ~10836)
The page and the confirm() say "Permanently delete ... cannot be undone", but the route moves the
campaign to the trash, where it can be restored for `TRASH_TTL_DAYS`. Change the copy to say
it moves to the trash and can be restored for N days (pass the real number in). Fix the route's
docstring too. Keep the confirm() string JS-escaped (inline handler rule).
- Test: `tests/test_campaign_soft_delete.py`: the page no longer says "cannot be undone" and
  shows the day count.
