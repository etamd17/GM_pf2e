# MB-09: stopping a metalmind is free

<!-- ============ BRIEF (written before work starts) ============ -->

- **Owner:** claude (rules engine). Codex reviews.
- **Branch:** `claude/mb-09-free-metalmind-stop` from `origin/main`.
- **User ruling (2026-10-28):** "make stopping a metalmind free."
- **Found in:** MB-07's browser pass. A Feruchemist who started storing could not stop in the same
  turn. The engine refused with "A named action can normally be used only once per turn", because
  the stop ran through the same action row as the start: it checked and consumed the action's
  once-per-turn slot and charged its action cost.

## Rule

A Feruchemy `store_stop` or `tap_stop`:

- spends no action and no reaction;
- neither needs nor uses the action's once-per-turn slot.

Starting a store or tap keeps its catalog cost and its once-per-turn limit, so stopping and then
starting again in the same turn is still refused. Allomancy is unchanged.

## Report (Claude, 2026-10-28)

- **Code:** `compile_mistborn_action` marks a stop command `stopping`. Its action row then costs
  `free` and has `allow_multiple`, so `apply_action_transaction` skips the named-action check and
  records nothing. The runtime operation, effect removal and receipt are unchanged.
- **Test:** `test_mistborn_api.py::test_stopping_a_metalmind_is_free_in_the_same_turn`, for both
  store and tap, with the private data:
  - start, then stop in the same turn: 200, actions remaining unchanged by the stop, mode back to
    idle;
  - a second start in that turn: still 409 `named_action_used`.
- **Results:** with the 1.1.2 bundle, the Mistborn API, runtime and duration suites plus the action API
  give 174 passed. The new test needs the private bundle, like the rest of that file.
