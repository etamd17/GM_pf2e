# MB-08: power talent trees require the power

<!-- ============ BRIEF (written before work starts) ============ -->

- **Owner:** claude (rules engine). Codex reviews.
- **Branch:** `claude/mb-08-talent-trees` from `origin/main`.
- **Found in:** MB-07's browser pass. The engine accepted Heavyweight Blow (a `feruchemy.iron`
  tree talent) for a Mistborn with no Feruchemy, because its only prerequisite is a runtime
  condition (`currently_tapping_weight`), which acquisition treats as met.

## Evidence (installed 1.1.2, both eras)

- Each metal's talents form that power's tree, recorded in the talent's `tree_memberships`, such
  as `feruchemy.iron`.
- 157 talents sit only in power trees. 45 are roots that list `power:<art>.<metal>` (the power must
  be unlocked). Most of the rest chain from a root through `talent:` prerequisites.
- **16 have neither.** Their only prerequisites are runtime conditions or ranks, so the engine let
  anyone take them:
  - Controlled Burst and Selective Burst;
  - Searing Palm, Thermal Conduction, Drowsy Storing, Reflexive Bloodmaker, Featherweight Slip,
    Heavyweight Blow, Run It Back, Sparked Aid, Think Again;
  - Pewter Pitcher and Pewterarm Weaponcraft;
  - Peak Condition, Feruchemical Endurance and Not Quite Yet.
- Each of these, by its own wording, needs the power in play (for example "currently tapping
  weight", or "burning pewter or tapping strength").

## Rule

A selected talent whose **every** tree is a power tree (`allomancy.<metal>` or
`feruchemy.<metal>`) needs at least one of those powers, with the same meaning as a `power:`
prerequisite: the power is unlocked.

- Talents that also sit in a path tree (for example `twinborn` plus `allomancy.iron`) are left to
  their listed prerequisites.
- Builds without catalog rules are unchanged.
- No data is edited. This is acquisition validation only.

## Report (Claude, 2026-10-28)

- **Code:** `MistbornBuild._record_issues` adds the tree check after the prerequisite check. The new
  hard violation reads "Talent X belongs to the talent tree of a power this character does not have
  unlocked."
- **Tests:** `tests/cosmere_rules/test_mistborn_talent_trees.py` uses synthetic rules only, so it
  runs in CI:
  - refused without the power;
  - still refused while the power is nascent or goal-active;
  - allowed once it is unlocked with its server entitlement;
  - mixed and path-only trees untouched;
  - nothing changes without catalog rules.
- **Results:**
  - The new file plus `test_mistborn_build` and `test_mistborn_advancement`, without the bundle:
    56 passed.
  - With the 1.1.2 bundle (talent trees, build, advancement, API, projections, mixed-world profiles):
    150 passed.
- **Effect on saved characters:** a character already holding one of the 16 talents without the
  power now shows a hard violation the next time it is edited. Opening the sheet does not change
  the file. The GM override still saves.
