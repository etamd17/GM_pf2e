## Context

- Roshar money is `systems/cosmere/spheres.py`: integer values in diamond chips, a versioned
  wallet (`normalize_wallet` returns `{version: 2, spheres: {gem: {chip, mark, broam}}, items}`),
  `wallet_total` and `format_marks`. `app.py` imports them around line 12171 for the loot ledger
  (~12206), the wallet totals (~12408, ~12493) and the sheet (~15717).
- The world comes from `app.py::_cosmere_world()`, and templates get `cosmere_world` from the
  context processor. Mistborn campaigns currently show and award **Roshar spheres** in wallets
  and on the loot page.

## Goal

Under the Mistborn world, character wallets and the loot page use boxings and clips: shown,
edited, awarded and totalled in them. Stormlight is unchanged, byte for byte.

## Approach

1. **The rate.** Take boxings-to-clips from the installed Mistborn rules bundle if it states one,
   and cite where in your report. If the bundle does not state a rate, **stop and ask** in your
   handoff; do not invent one. Keep values as integers in clips, so nothing passes through
   floating point, as `spheres.py` does with chips.
2. **A separate module and wallet,** e.g. `systems/cosmere/scadrial_money.py`, with the same
   shape of API as `spheres.py`: normalize, total and format.
   - Store the money under its own key in the character's wallet (for example
     `wallet["scadrial"] = {"version": 1, "boxing": n, "clip": n}`) **beside** `spheres`, never
     inside it.
   - A sphere wallet and a Scadrial wallet never convert into each other. A Mistborn character
     with existing sphere counts keeps them untouched. Show them read-only, labelled as Roshar
     spheres, only if any exist, and report how many such characters your fixtures and the dev
     data have.
3. **Opening never rewrites a file.** That is the same rule as UI-05: a character gains the new
   key only on its next real save. Test it.
4. **The loot page:**
   - Mistborn campaigns award boxings and clips;
   - a ledger entry records which currency it used;
   - deleting an award reverses exactly what it credited, as UI-05's gem-isolated reversal does,
     and can never debit the other currency;
   - totals per character and per party are in boxings and clips.
5. **The sheet:** the wallet editor and the total under the Mistborn skin show boxings and clips,
   and live repaint keeps working (check `_pc_state_payload` / the Cosmere equivalent ships it).
6. **Systems never share mechanics:** nothing PF2e or D&D changes. The Stormlight wallet, loot
   and sheet output must be identical before and after; a regression test compares them.

## Accept

- Tests for:
  - the integer value math, and normalization of missing, partial and bad input;
  - open-without-rewrite;
  - award, delete and exact reversal in both worlds, including that a Mistborn award can never
    touch spheres and a Stormlight award never touches boxings;
  - the loot totals;
  - the sheet wallet round-trip;
  - Stormlight unchanged.
- All templates parse; the full Cosmere suite passes.
- Report the rate and its source, the files touched, and real test numbers.

### Rate and saved format

**1 boxing = 100 clips**, for both eras. Source: installed private bundle `cosmere_data/rules/mistborn/core-1.1.0.json`, records `mistborn.currency.boxing` and `mistborn.currency.clip`, `parameters.data.boxing_value` (1 and 0.01). Both records apply to Era 1 and Era 2 and cite the Mistborn handbook, printed **254**, PDF **257**. No book prose or bundle contents are added to git.

Money is stored beside spheres as `wallet.scadrial = {version: 1, boxing, clip}`. All calculations use integer clips. Formatting divides by 100 with integer remainder; banknotes have no third balance. Counts are limited to 10^12 per denomination to retain exact browser integers. Invalid writes are refused rather than rounded.

A display-only normalization returns a detached copy. It preserves the original sphere stash and shape, rather than converting or upgrading it. Merely opening the sheet does not save or touch its modification time. A real money save/award adds the key. Stormlight mutations retain an existing Scadrial stash instead of dropping it.

### Implementation

- `systems/cosmere/scadrial_money.py`: normalization, strict write validation, integer totals and display formatting.
- `app.py`: world-specific loot view/totals and award dispatch; new Scadrial awards carry `currency: scadrial` and their original denomination counts. Deletion dispatches from the recorded currency even if the current world has changed. A spent boxing cannot be reversed from an equal-value clip stash, and goods must also be available before any write. Existing wallet/ledger locks and rollback behavior remain in place.
- `app.py`: owner/GM-only `POST /cosmere/pc/<pid>/wallet`, restricted to the Mistborn world. The locked update compares the submitted original money balance to the latest balance, so a stale editor cannot overwrite intervening loot. It touches only Scadrial money. `core/route_policy.py` and the retained-character write inventory register it alongside the other Cosmere character endpoints.
- `templates/cosmere_loot_mistborn.html`: inherits the existing ledger CSS, with boxings/clips, per-character and party wallet totals, plus separate historical Roshar award labels. The existing Stormlight loot template is untouched.
- `templates/_cosmere_scadrial_wallet.html`, `static/js/cosmere_scadrial_wallet.js`: Mistborn-only editor, server totals, shared SSE hub subscriptions to loot and player-state changes, safely rendered goods, and read-only legacy Roshar spheres. An unsaved editor retains its original comparison base when a later frame arrives, rather than silently rebasing a stale write. No inline user-controlled JavaScript handlers were added.
- `templates/cosmere_sheet.html`: select the Mistborn include and its listener only for that world. The Stormlight wallet markup and loot listener render byte-for-byte as before; regression hashes were captured from the pre-MB04 template. The Stormlight ledger file also has an unchanged-content hash gate.
