# MB-11: load the Cosmere rules once, show the installed release, close the rules side door

<!-- ============ BRIEF (written before work starts) ============ -->

- **Owner:** claude (rules loader, saved campaign config). Codex reviews.
- **Branch:** `claude/mb-11-rules-load` from `origin/main` (`ce77d7e8`).
- **Found in:** the check of the user's production install of the reviewed 1.1.2 bundle
  (2026-10-28). The install itself is verified. The check found four problems around it.

## Problems

1. **Every rules load stalls the whole site.** Production runs one gevent worker. The first Cosmere
   page after each deploy, restart or bundle install re-verifies the 3 MB registry, which freezes
   every request and live stream until it finishes. With 17 package versions that is about 20 s on a
   Windows dev machine (an estimated 9 to 10 s on Railway, up from about 4 s with 11 versions), and
   it grows with each release.
   - **Cause:** one `load_registry` serializes the whole registry 4 times, runs `validate_authoring`
     twice, and builds every package twice. Each serialization repeats `freeze`'s privacy checks
     (4 regexes per string, 3 more per key) on strings that already passed. `validate_authoring`
     also checks the same table graph 11 times out of 17.
   - An install verifies the tree, swaps it in, and then clears the cache, so the next page verifies
     the same files all over again.
2. **The admin page cannot say which release is installed.** It shows "Installed" and the folder.
   The upload message counts only the first version of each package (695 records for 1.1.0, 1.1.1
   and 1.1.2 alike), and the registry hash is only in the JSON response.
3. **`POST /api/campaign` accepts `rules_binding`, `cosmere_theme` and `cosmere_world` unchecked.**
   This lets a campaign be re-pinned after play starts, skipping the lock in `/api/cosmere/rules`
   and the Stormlight-under-Mistborn refusal in `/api/cosmere/world`. No page sends these keys (the
   only caller, `campaign_intro.html`, sends six fixed fields), and there were 0 calls in 7 days.
   The optional keys date from `bd250028`; MB-07 added the lock but left this route open.
4. **The bundle allows only 16 files.** 1.1.2 uses 13 and each release adds 3, so 1.1.4 would be
   refused as "too many files".

## Plan

- **Same checks, run once.** Every accept or reject decision must stay exactly as it is.
  - `freeze`: precompile its regexes and remember strings and keys that passed (bounded sets;
    failures are never remembered).
  - `check_json`: freeze's checks in the same order, without building the frozen copy. Use it where
    the copy was thrown away (`read_json`, `canonical_json`).
  - `load_registry`: validate once and reuse those packages. Compare the file's bytes with the
    compiler output first, and keep the old canonical comparison as the fallback for equivalent
    files that are not byte-identical.
  - `validate_authoring`: check the first-version table view once instead of once per first-version
    package.
- **Load once, at the right time.**
  - Load the registry at boot, with the same pytest and reloader-parent exemptions as the other
    autostarts. A failed load must never stop the site from booting; pages retry on use, and the
    admin page stays reachable for a fixed upload.
  - A bundle install hands its already-verified registry to the cache instead of clearing it.
- **Admin page:** show the newest Mistborn release, the older ones kept for pinned campaigns, the
  package-version count and the short registry hash, both on the page and after an upload. If the
  installed data fails to load, the page must still render and say so.
- **Side door:** `POST /api/campaign` refuses the three rules keys with a 400 that points at the GM
  hub, and refuses a body that is not a JSON object.
- **Bundle limit:** raise `MAX_MEMBERS` to 64. The 32 MiB unpacked cap remains the real bound. It
  will bind in about four more releases, so pruning old versions is a later decision for the user.

## Acceptance

- Equivalence tests: `check_json` raises exactly what `freeze` raises, in the same order, on a corpus
  of bad inputs. New `canonical_json` bytes equal the old formula's. `load_registry` still rejects a
  tampered hash, record or field, and still accepts a re-indented or CRLF registry with the same
  content.
- After an upload through the route, the next `default_registry()` returns the new registry without
  loading anything.
- The boot preload runs on a real import, is skipped under pytest, and survives a broken bundle.
- Before and after timings for one `load_registry` on 1.1.2, and for an install.
- The full suite passes, the template check passes, and the private-data suites pass with 1.1.2.

## Report (Claude, 2026-10-28)

### Timings (Windows dev machine, 1.1.2 data; Railway is roughly twice as fast)

| | main (`ce77d7e8`) | MB-11 |
|---|---|---|

| First Cosmere page after a deploy | pays a full load | nothing (loaded at boot) |

The loaded registry is identical: same 17 versions, 695 legacy records, hash `0d3e3e1b`, and the
same digest over every package, record and artifact.

### What changed

1. **Validation, same decisions** (`schema.py`, `compiler.py`, `registry.py`).
   - `freeze`'s regexes are precompiled. Strings and keys that passed are remembered in two sets
     with one shared hard bound (32,768 entries, 2M characters, strings up to 1,024 characters).
     The 1.1.2 registry needs 5,938 strings, 434 keys and 206,494 characters. Failures are never
     remembered.
   - `check_json` runs `freeze`'s checks in `freeze`'s order through the same walker, without
     building the copy. `read_json` and `canonical_json` use it; both used to build a frozen copy
     only to throw it away.
   - `to_dict` returns exact JSON types before the dataclass and ABC checks. They reach the same
     branch as before.
   - `load_registry` validates once (`compile_and_validate` returns what validation built) and
     reuses those packages. Its compiled-output check compares bytes first (CRLF-normalized, as
     `datapack._validate_tree` already did) and falls back to the old canonical comparison. The
     registry-hash check still runs first, so error precedence is unchanged.
   - `validate_authoring` checks the first-version table view once instead of once per
     first-version package. Every later version is still checked
     (`test_every_version_is_table_validated_not_only_the_legacy_id_view` passes).
2. **Load once** (`profiles.py`, `datapack.py`, `app.py`).
   - `default_registry` is a plain holder that keeps `cache_clear()`. `use_default_registry()`
     hands in a verified registry.
   - `datapack.install(..., loaded=...)` passes the verified registry once the new tree is live.
     The upload route uses it instead of clearing the cache.
   - `_autostart_cosmere_rules()` runs at the module tail, after the autosave restore, with the
     same pytest and reloader-parent exemptions as `_autostart_persistence`.
     `_preload_cosmere_rules()` catches everything and logs `[COSMERE] Rules not loaded at boot`,
     so a bad bundle cannot stop the site booting.
3. **Admin page.** It shows "Installed: Mistborn rules 1.1.2", the package-version count, the short
   registry hash, and "Also kept for campaigns pinned to them: 1.1.0, 1.1.1". The upload response
   adds `release` and `older_releases` (the existing keys are unchanged). If the installed data
   fails to load, the page still renders, names the error and keeps the upload button.
4. **Side door.** `POST /api/campaign` returns 400 (`fields` lists the offenders) for
   `rules_binding`, `cosmere_theme` or `cosmere_world`, and for a body that is not a JSON object.
   It used to 500 on a list. The intro page's six fields still save.
5. **Bundle limit.** `MAX_MEMBERS` is now 64 (20 releases). The 32 MiB unpacked cap binds first,
   in about four more releases, and that is when pruning old versions becomes the user's call.

### Tests

- `test_registry_load.py` (new, 100 tests). The oracle is a verbatim copy of the replaced
  `freeze`, `to_dict` and `canonical_json`.
  - A corpus of 17 good and 30 bad inputs (media payloads, every absolute-path form, forbidden and
    camel-cased keys, empty and non-string keys, NaN, depth 32 and 33, sets, IntEnum, bytes, error
    order) must get the old verdict, message and output from `freeze`, `check_json` and
    `canonical_json`, twice.
  - Bytes are compared on real packages, records, artifacts and both binding shapes.
  - `load_registry` must still refuse a bad hash, an edited record, reordered packs and an extra
    field, and still accept a re-indented or CRLF registry.
  - It also checks the remembered sets stay bounded.
- `test_datapack.py`: the upload serves the verified registry (a second load fails the test). The
  admin page names the release; it still renders when the registry is broken. 22 files install and
  72 are refused.
- `test_rules_boot_load.py`: a broken bundle leaves boot alive. A fresh `import app` with an
  installed bundle loads it, checked by hash.
- `test_campaign_rules_switch.py`: each rules field and a list body are refused with nothing
  written, and the intro fields still save.
- **Independent review (Claude workflow, 2026-10-28).** Four reviewers worked in their own
  worktrees. A usage limit cut them off before they reported, so their saved outputs were read and
  the unfinished checks were completed by hand:
  - **Differential fuzzing, old against new:** about 64,000 comparisons, covering:
    - `freeze`, `check_json`, `to_dict`, `canonical_json`, `package_hash` and `read_json` on
      random and real values;
    - `load_registry` on 2,000 mutated fixture registries, 156 mutated 1.1.2 registries and 120
      rewrites;
    - `compile_registry` on 1,000 mutated authoring documents;
    - the datapack paths.

    It found no divergence in any accept or reject decision on realistic input. The only
    differences:
    - 17- and 20-file bundles now install (the intended limit change).
    - Structures nested about 495 or more levels deep, far beyond the 32-level limit, reach
      Python's recursion limit at a slightly different depth. Both versions still refuse them, but
      the message can differ, and in a two-level window MB-11 raises the validation error where
      main raised a RecursionError.
  - **Remembered-pass soundness:** every check passes. No remembered string can skip a check it
    would otherwise fail (str subclasses with colliding hash and equality, a value later used as a
    key, the depth limit after remembering, churn with a tiny limit, Unicode variants). With 200,000
    hostile strings, the sets peaked at 7.2 MiB and 32,328 entries.
  - **Boot and state:** the boot load runs on a production-style import and in the reloader child.
    It is skipped under pytest and in the reloader parent (`FLASK_DEBUG=true`), survives a truncated
    registry, and loads the bootstrap when nothing is installed. Three back-to-back uploads under
    gevent each hand over their own registry, and what is served matches the disk. Running the
    Cosmere suites in forward, reverse and shuffled order leaks no state.
  - **Side doors:** `POST /api/campaign` refuses all three fields in every spelling tried (escaped,
    duplicated, all at once), and non-object bodies now get 400 instead of 500.
  - **Mutation testing:** 57 one-line regressions were applied to the implementation, one at a
    time.
    - The first test set missed four. The resulting additions are in `c18f0816`; each kills a named
      mutant.
    - With them, 55 of 57 are caught. The two survivors behave the same as the real code on
      anything a registry can contain: a `to_dict` fast path using `isinstance(value, dict)`, and
      building the legacy view in compiled order (an accepted file is always in compiled order).
  - **Not MB-11, recorded for later:**
    - `/campaign/import` restores a backup's rules fields unvalidated. That is right for a real
      restore and only creates the importer's own campaign, but a hand-edited backup can store an
      invalid binding, which fails closed on use.
    - With `FLASK_DEBUG=1` (as `flask run --debug` sets it), the reloader parent also loads the
      rules. `_autostart_persistence` uses the same check, and in dev it only costs a few seconds.
    - A crash exactly between the installer's two renames leaves no installed tree until the next
      upload.
- **CI found one test using the side door as a setup shortcut.**
  `test_campaign_containment.py::test_public_template_context_does_not_inherit_live_campaign_chrome`
  set `cosmere_world` through `POST /api/campaign` before checking that logged-out pages do not
  inherit the live campaign's settings. Its check is unchanged; it now sets the world through
  `POST /api/cosmere/world`, the route that owns it. CI otherwise passed: 4,284 passed, 134
  skipped.
