# 5E-06: Delete combatant pictures that nothing uses any more

<!-- ============ BRIEF (written before work starts) ============ -->

- **Owner:** codex
- **Branch:** `codex/5e-06-image-gc` from `feature/dnd5e` (or `main` once merged)
- **Depends on:** none
- **Context:** `docs/dnd5e/HANDOFF.md` > Images > Uploads; `systems/dnd5e/images.py`;
  `routes.py::api_gm_combat_image`; `service.py::combat_action` (`'clear'` ~line 810,
  `'remove'` ~line 813)

## Goal
GM art uploaded for a tracker combatant is left on disk when the picture is replaced,
the combatant is removed, or the encounter is cleared. Delete those files, without ever
deleting one still in use.

## Approach
- Add `images.collect_garbage(cid, keep: set[str]) -> int` that deletes every file in
  `images_dir(cid)` matching `NAME_RE` whose name is not in `keep`, skipping files
  modified in the last 10 minutes (an upload whose row isn't saved yet).
- `keep` = every `portrait` in `store.list_pcs(cid)` plus every combatant `image` in
  `store.load_encounter(cid)` plus every `image` in saved plans if plans ever gain one
  (they don't today -- leave a comment).
- Call it after `'clear'` and `'remove'` in `routes.api_gm_combat`, and after a
  replace in `api_gm_combat_image`. Wrap in try/except OSError: GC must never fail a
  request.

## Acceptance
- [ ] Replacing, removing, or clearing deletes the orphaned file; a PC portrait and an
      image still on another combatant survive.
- [ ] A file younger than 10 minutes is never deleted.
- [ ] New tests in `tests/test_dnd5e_images.py`; `pytest -q tests/test_dnd5e_images.py
      tests/test_dnd5e_app_integration.py` passes.
- [ ] HANDOFF.md: remove the "combatant art is not deleted" bullet.

## Out of scope / do not touch
- PC portrait deletion (already correct), the 5etools art under `static/dnd5e_img/`.
