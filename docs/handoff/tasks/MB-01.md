## Goal
Get MB-00's backend onto current `main` with every test green, as a PR the user can merge. No UI
redesign (that comes later, per MB-00).

## Approach
1. Merge `origin/main` into the branch (it is 43 commits behind). Expected conflicts: only
   `core/storage.py`, where both sides add folder helpers next to each other. Keep both sets
   (`cosmere_*_file` and `dnd5e_dir` / `dnd5e_pc_dir`). `app.py` merges automatically, but check
   that the 5e blueprint registration and redirects (bottom of `app.py`) and the new Cosmere
   routes both survive.
2. Run the full standard gate: `python -m pytest -q -m "not postgresql and not browser" --strict-markers`.
   MB-00 reports an order-dependent failure here (PF2e rules region, then campaign/chronicle tests).
   The last full run on `main` (2026-10-12) had 0 failures, so assume this branch causes it until
   shown otherwise. Likely suspects: module-level state or caches added in `systems/cosmere/rules/`
   or new app globals that leak between tests. Find the first failing test in a full run, then
   bisect by test file.
3. Add every new route to `core/route_policy.py` if any are missing (`tests/test_route_policy_inventory.py`).
4. **Move the Mistborn data out of git** (user decision 2026-10-13: the repo is public).
   - Data files (`data/cosmere/rules/mistborn/`, `mistborn_coverage.json`, `authoring.json`, and
     any other book-derived records) move to a gitignored folder, e.g. `cosmere_data/`, found the
     same way as the 5e data: env var, else `<DATA_DIR>/cosmere_data` on the Railway volume, else
     the repo folder in dev. Model it on `systems/dnd5e/paths.py`.
   - Install on the server like the 5e data: a bundle tool plus a site-admin upload page. Reuse the
     approach in `systems/dnd5e/datapack.py` (allow-listed names, size caps, validate before
     writing, atomic swap, then clear caches).
   - Without the data installed, Mistborn features must say "not installed" instead of crashing,
     and Stormlight campaigns must keep working exactly as today.
   - **Tests:** CI cannot rebuild this data (it came from the books, not a public source). Commit
     a small *made-up* fixture package (invented names and numbers, a handful of records per type)
     under `tests/fixtures/` and point the tests at it. Tests that truly need the real data skip when
     it's absent. CI must still run the kernel, advancement, actions and migration tests against
     the fixtures.
   - Make sure no real record survives in git history: the branch isn't pushed yet, so remove the
     data from the commits (rewrite the local branch, or squash) before the first push.
5. Push the branch and open a PR. Don't merge.
