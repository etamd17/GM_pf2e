### How to test or view the checkpoint

- From the repository root, extract with `Expand-Archive -LiteralPath docs/handoff/assets/UI-00-review.zip -DestinationPath docs/handoff/assets/UI-00-review`. Use a new destination; do not overwrite an existing review directory.
- Open the extracted `*-review-offline.html` files directly in a browser. Keep the other files beside them so their iframes resolve. The bundle's PNGs provide an alternative if browser previews fail. Prior desktop inline views showed code and local HTTP was unreliable; direct file pages plus screenshots worked.
- In that extracted directory, run `node capture-cosmere-gmscreen-review.js` and `node capture-cosmere-loot-review.js` with Node, Playwright and Chrome installed at the paths named in those scripts. On another machine, adapt those paths first. The saved HTML fixtures suffice for these checks; do not start the production app.
- The render scripts additionally need Flask/Jinja and the exact repository snapshot. `serve-pf2e-dashboard-review.py` defines a safe fixture Flask app without importing product `app.py`; keep that separation.
- GM Screen checks retain ten sections/eight tables and exercise pins, topics, search, anchors/cross-links and 390px layouts. Loot checks retain original fields/options and six example records, exercise local item rows, filtering and draft updates, distinguish failed loading from empty data and verify writes are blocked. No success response from a real endpoint is tested.
- Browser capture blocks remote fonts, so screenshots can use fallback faces. Mock transport, storage and event messages are intentionally disconnected from the real table.

### Anything broken or risky

These are findings from this snapshot, not claims about current production. Reproduce against current trunk before fixing them; detailed notes are in the bundled decision log.

- [PF2e GM Screen](../../../templates/gmscreen.html): its polish script targets `.masonry`, but the template uses `.gm-group-grid`, so enhancements fail to initialize.
- [PF2e level-up](../../../templates/player_levelup.html): the gains rail can intercept picker clicks. Prototypes adjust stacking and relocate the same override control, but real GM authorization remains untested.
- [PF2e builder](../../../templates/player_builder.html): review validation treats a selected ancestry-feat object as a string and calls `toLowerCase()`; review also reads stale class/spell fields. Prototype normalization is not a deployed fix.
- [Map client](../../../static/js/map.js): no-scene early return runs before `toastTimer` initialization; failed first-scene creation can throw instead of showing the error. Map-first approval does not authorize changing the GM-only shared-table model.
- [Cosmere tracker](../../../templates/tracker.html): PF2e MAP/agile guidance, quick conditions, persistent-damage guidance and elite/weak controls appear in Cosmere fixtures. Preserve tools, but do not bless this vocabulary as correct Cosmere mechanics.
- [Cosmere roster](../../../templates/cosmere_pcs.html) and [Vitals](../../../templates/cosmere_gm_vitals.html): roster has no live repaint and shows maximum Investiture; Vitals relies on initial maximums and name-keyed cards. Reconnect, renamed/new characters and changed maxima are not proven by local fixture repaint.
- [Cosmere GM Screen](../../../templates/cosmere_gmscreen.html): Mistborn skin still receives Stormlight reference content; the route shows nine player-playable orders, not the separate Bondsmith reference. No completeness/rules decision was made in the UI review.
- [Cosmere loot](../../../templates/cosmere_loot.html) and [routes](../../../app.py): total ignores gem value, wallet credit drops gem identity, party awards remain ledger-only and deleting logs does not reverse credits. Ledger write precedes wallet write; failure/duplicate/invalid-input coverage is still needed. The source client does not reliably check HTTP/success status before clearing the draft.
- [Campaign templates](../../../templates/campaign_invites.html): deletion wording differs from soft-delete behavior, and expiry differs by storage backend. Opening production invites can mint claim links; it is not a strictly read-only inspection.
- Offline fixtures do not verify publication, private-note access, account isolation, backups or live synchronization. Do not mark broader PR acceptance complete based on these UI checks.
- Two unrelated untracked campaign Markdown plan/spec files remain in the working tree. They were present before this task and are intentionally not in this commit. The changed handoff protocol in the sibling checkout also remains untouched.
